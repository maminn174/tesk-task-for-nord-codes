# Автоматизированные тесты API

Интеграционные тесты приложения Spring Boot с аутентификацией по токенам и выполнением пользовательских действий.

## Технологии

- Java 17+
- JUnit 5
- REST Assured
- WireMock
- Allure Report
- Apache Maven

## Описание приложения

Приложение предоставляет единственную точку входа: `POST /endpoint`.

| Действие | Описание |
|----------|----------|
| LOGIN | Аутентификация токена через внешний сервис |
| ACTION | Выполнение действия с аутентифицированным токеном |
| LOGOUT | Удаление токена из внутреннего хранилища |

Внешний сервис имитируется с помощью WireMock.

## Покрытие тестами

- Успешная и неуспешная аутентификация
- Повторные попытки входа
- Действия с авторизацией и без неё
- Ошибки внешних сервисов
- Жизненный цикл сессии и выход
- Валидация токенов
- Проверка ключа API
- Изоляция токенов разных пользователей

## Требования

- Java 17 или новее
- Apache Maven
- Windows с PowerShell
- JAR-файл приложения, предоставленный вместе с заданием

## Запуск тестов

Запустите приложение:

```powershell
java -Dsecret=qazWSXedc -Dmock=http://localhost:8888/ -jar internal-0.0.1-SNAPSHOT.jar
```

Приложение работает на порту 8080. Из каталога тестового проекта выполните:

```powershell
mvn clean test
```

WireMock запускается автоматически на порту 8888.

Также можно воспользоваться скриптом PowerShell:

```powershell
.\run-tests.ps1 -JarPath "C:\path\to\internal-0.0.1-SNAPSHOT.jar"
```

Скрипт запускает приложение, выполняет тесты и затем останавливает приложение.

## Отчёты о тестировании

Создайте и откройте отчёт Allure:

```powershell
mvn allure:serve
```

Результаты тестов сохраняются в `target/allure-results`.

## Известные ошибки

### BUG-001: Допустимые токены с буквами G-Z отклоняются

**Ожидаемое поведение:** согласно спецификации API, токен должен состоять ровно из 32 символов из диапазонов A-Z и 0-9.

**Фактическое поведение:** приложение проверяет токены по регулярному выражению `^[0-9A-F]{32}$`. Поэтому токены с буквами G-Z отклоняются с HTTP 400.

**Статус:** известная ошибка. Соответствующий тест помечен `@Disabled`, чтобы основной набор тестов можно было выполнять.

## Примечания

- Тесты используют уникальные токены для уменьшения конфликтов состояния.
- Ответы внешнего API имитируются с помощью WireMock.
- Тесты проверяют ответы API и обращения к внешним сервисам.
- JAR-файл приложения не входит в репозиторий.
- Ответы HTTP 500 при сбоях внешних сервисов отражают наблюдаемое поведение; спецификация API явно его не определяет.
